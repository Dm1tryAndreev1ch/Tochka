# Этап A воспроизводимый паспорт запуска

`scripts/runtime_manifest.py` формирует JSON-паспорт исходников, выбранных моделей, безопасной части конфигурации и окружения Python. Его `semantic_sha256` можно прикладывать к trace и результатам испытаний, чтобы отличать замеры разных конфигураций. Паспорт не запускает inference, не скачивает модели, не обращается к сервисам и сам по себе не является результатом бенчмарка или подтверждением безопасности выпуска.

## Использование

Проверка без записи файлов и без чтения больших весов:

```sh
.venv/bin/python scripts/runtime_manifest.py --dry-run
.venv/bin/python scripts/runtime_manifest.py --role llm --dry-run
```

Для сохранения укажите новое имя JSON-файла. Существующий файл не перезаписывается:

```sh
.venv/bin/python scripts/runtime_manifest.py --output artifacts/baselines/runtime-001.json
```

Для явной проверки байтов выбранных моделей:

```sh
.venv/bin/python scripts/runtime_manifest.py --verify-models --output artifacts/baselines/runtime-verified-001.json
```

Последняя команда читает гигабайты весов и может занять заметное время. На Windows используйте `py -3.12` или Python виртуального окружения. Роли `app`, `llm`, `tts` определяют, какие модели считать выбранными; для удалённого LLM приложение фиксирует `remote_runtime_not_observed`, а worker должен выпустить собственный паспорт с ролью `llm`.

CLI намеренно не читает `.env`. Он использует только безопасные поля окружения процесса и простые defaults из исходного `app/config.py`; модуль `app.config` не импортируется. Поэтому самостоятельный CLI без экспортированных настроек не отражает переопределения, которые находятся только в `.env`. Для точной привязки к запуску launcher передаёт фактически выбранную конфигурацию через API.

## Контракт интеграции

```python
from scripts.runtime_manifest import collect_runtime_manifest, write_runtime_manifest

manifest = collect_runtime_manifest(
    root=project_root,
    config=effective_environment,  # mapping после выбора профиля и аргументов launcher
    verify_models=False,
    role="app",
)
write_runtime_manifest(unique_json_path, manifest)
runtime_manifest_id = manifest["semantic_sha256"]
```

`config` принимает mapping с верхним регистром переменных окружения или нижним регистром полей Settings. При одновременном наличии одного поля в двух регистрах верхний имеет приоритет. Можно передать mapping с другими полями: функция запрашивает только известные разрешённые ключи и не сериализует остальные. Она не должна получать произвольную строку dotenv или путь к файлу секретов. Значения worker-параметров `context`, `threads`, `gpu-layers` должны попасть в mapping после применения CLI overrides.

`collect_runtime_manifest` выполняет только чтение; `write_runtime_manifest` создаёт новый `.json`, делает flush/fsync и отказывается заменять существующий файл или символическую ссылку. При обработанной ошибке записи созданный неполный файл удаляется. После аварийного отключения питания недописанный JSON не является валидным паспортом. Ссылка на паспорт публикуется только после успешного возврата функции записи. Для каждого запуска нужен отдельный путь; абсолютный путь не требуется включать в telemetry, достаточно digest и внутреннего ID артефакта.

## Что фиксируется

**Исходники.** Сохраняются HEAD commit, SHA-256 содержимого разрешённых файлов и два агрегатных digest: `source.tree_sha256`, `source.changes_sha256`. Сравнение с Git HEAD отмечает изменённые, добавленные и удалённые файлы; новые незакоммиченные файлы тоже входят в snapshot. Содержимое diff, сообщения commit, remote URL и авторы Git не сохраняются. `dirty_scoped` относится к разрешённому набору исходников, а не объявляет весь repository чистым. Без Git fingerprint файлов остаётся доступным, но HEAD и состояние относительно него неизвестны.

Область включает код из `app`, `scripts`, `tests`, `native`, `launchers`, schema migrations и явно перечисленные файлы зависимостей/сборки. Исключены `.env`, скрытые/private каталоги, ключи, credentials, cache, uploads, recordings, архивы, test fixtures и произвольные assets. Строки путей ограничены относительными путями исходников; symlink исходника не раскрывается и делает `fingerprints_complete=false`. Файл более 32 MiB не читается как исходник. Три утверждённых файла `app/assets/voices/{male.wav,female.wav,metadata.json}` хешируются отдельно; их содержимое в JSON не входит. Это ограниченная область, а не доказательство охвата любого произвольного нового runtime-ресурса.

**Конфигурация.** Разрешены выбор STT, режим LLM, поддерживаемый model alias/prompt profile, context/reply budgets, threads/GPU layers, параметры VAD/preemptive STT, streaming/cache TTS и голосовые presets. Числа проверяются по диапазону, строки — по известным значениям. Неизвестные значения заменяются маркерами `custom-value-redacted`/`invalid-redacted`, а не печатаются. URLs, IP, DB DSN, пароли, cookies, API keys, prompts, контакты, содержание разговора и имена клиентов не включаются. Пути моделей заменяются сведением об известном layout либо `custom-path-redacted`; абсолютный путь и имя владельца компьютера не сохраняются.

**Модели.** Источники ожидаемых сумм — существующий `model-manifest.json` и закреплённый `scripts/model-download-catalog.json`; актуальный каталог имеет приоритет. В snapshot попадают только известные артефакты выбранной роли, допустимые repository ID, полный revision, размер и SHA-256. По умолчанию это `provenance=...:declared-snapshot`, `verified=false`, `verification=not_verified`: manifest прошлого скачивания не доказывает текущее состояние файла. Только `--verify-models` вычисляет фактический digest и сравнивает его с ожидаемым. Несовпадение, отсутствие файла и неподдерживаемый путь явно отмечаются. Нестандартные модели требуют осознанного расширения каталога/allowlist, иначе они остаются непроверенными.

Проверка моделей допускает чтение внешней model-ссылки только при совпадении конечного имени с известным локальным или закреплённым upstream-именем и безопасном расположении; ссылка на `.env` или каталог секретов не раскрывается. Этот паспорт не изменяет модели или ссылки. Удалённый worker и отдельно собранные native binaries не объявляются проверенными по локальным метаданным. Для нестандартного `VOICE_REFERENCE_DIR` встроенные образцы остаются fingerprint bundled assets, а выбранные внешние references отмечаются как непроверенные.

**Окружение.** Фиксируются версия/реализация Python, ОС с числовой частью release, архитектура, логическое число CPU, доступный через stdlib объём физической памяти и версии выбранных Python-пакетов. Не сохраняются hostname, username, абсолютный executable path, список процессов или полное окружение. `nvidia-smi`, shell/system hardware probes и импорты model runtimes не выполняются; GPU и версии native binaries остаются `not_probed`.

## Как интерпретировать digest

`semantic_sha256` вычисляется по canonical JSON семантических разделов: schema version, роль, исходники, очищенная конфигурация, замечания конфигурации, модели, references и runtime. Время `captured_at`, описание источника mapping и поясняющие ограничения в него не входят. Одинаковый snapshot даёт одинаковый digest, а изменение покрытого исходника, разрешённой настройки, наблюдаемого model digest или версии пакета меняет его.

Одинаковый digest двух паспортов с непроверенными моделями подтверждает совпадение заявленных метаданных, а не байтов моделей. Такой паспорт не заменяет freeze конфигурации перед испытанием. На время сбора следует завершить редактирование исходников; изменение размера/mtime файла во время чтения отмечается, но весь repository не блокируется общей транзакцией. Маркеры redacted/custom и непроверенные remote/native/GPU компоненты означают границы воспроизводимости, которые нужно закрыть перед строгой приёмкой соответствующего профиля.

## Проверка этапа

Изолированные тесты: `python3 -m unittest discover -s tests -p test_runtime_manifest.py -v`. Они проверяют, что poisoned `.env`, private fixtures и uploads не открываются, секретные/неизвестные поля и абсолютные пути не появляются в JSON, tracked/untracked изменения меняют fingerprint, timestamp не меняет семантический digest, model metadata остаются непроверенными без opt-in, повреждённые fixture weights дают mismatch, а существующий output не перезаписывается. Большие рабочие веса в этих тестах не используются.

Интеграция launcher/trace и привязка фактических ASR/LLM/TTS испытаний к этому ID выполняются отдельно. Прохождение тестов паспорта не означает прохождение голосового acceptance-набора.
