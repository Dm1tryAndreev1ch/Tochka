# Запуск и работа с Точкой

## Установка на Mac

Нужны Python 3.12, Docker с работающим daemon и llama.cpp. На этом Mac Python и Docker уже были установлены; llama.cpp установлен в ходе разработки. STT/TTS требуют macOS 14+ для текущего набора wheels. Windows-профиль пока не проверен.

```sh
brew install python@3.12 llama.cpp whisper.cpp ggml rubberband
python3.12 scripts/setup.py
```

Установщик проверяет свободное место, создаёт `.env` со случайными паролями, Python-окружение, PostgreSQL/EspoCRM и API-пользователя, затем загружает около 4.8 ГБ рабочих моделей. Python-окружение размещено в `~/.cache/voice-desk/venv`, чтобы iCloud не выгружал его файлы. В проекте `.venv` — ссылка на него. `requirements.lock` фиксирует точные версии; `model-manifest.json` содержит revisions, размеры и SHA256 весов. Уже установленная модель проверяется перед повторным скачиванием.

```sh
.venv/bin/python scripts/run.py
```

Можно также открыть `Start.command`. После прогрева:

- Клиент: <http://127.0.0.1:7860/>
- Кабинет: <http://127.0.0.1:7860/operator>
- EspoCRM: <http://127.0.0.1:18081/>
- Документация API: <http://127.0.0.1:7860/docs>

Пароли находятся в закрытом файле `.env`: `ADMIN_PASSWORD` — администратор кабинета, `OPERATOR_PASSWORD` — оператор кабинета; для EspoCRM логин `admin`, пароль `CRM_ADMIN_PASSWORD`. API-ключи доступны только серверу. Не публикуйте `.env`, `.runtime`, резервные копии и browser traces.

`Ctrl+C` останавливает процессы, запущенные launcher. `Stop.command` останавливает последний launcher; контейнеры БД/CRM остаются включёнными. Их можно остановить командой `docker compose stop`; данные сохраняются в именованных volumes. Не используйте `docker compose down -v`, если нужны сохранённые обращения.

## Проверить помощника

Компания «Точка», её адрес и услуги вымышлены. Это явно написано в интерфейсе и знаниях.

1. Отметьте согласие на хранение текста и заявки. Аудиозапись на диск выключена.
2. Нажмите «Начать разговор» и разрешите микрофон. Либо введите вопрос в чат.
3. Спросите «Сколько стоит консультация?» — цена берётся непосредственно из каталога.
4. Скажите «Хочу записаться на консультацию завтра в одиннадцать. Меня зовут Тестовый клиент, телефон +375291234567».
5. Проверьте сводку. «Нет, лучше в двенадцать» меняет черновик и отменяет старое подтверждение. «Да, подтверждаю» сохраняет новую запись.
6. Сохраните ссылку управления из карточки результата. Она разрешает только просмотр, перенос и отмену одной записи. Телефон и имя доступа не дают.

Форма услуги позволяет выбрать свободный слот и проверить все поля до подтверждения. При изменении цены, расписания или занятом слоте сервер отклоняет устаревшие детали. Один подтверждённый слот нельзя занять дважды, включая пересечение услуг разной длительности.

## Оператор

«Обращения»: найдите заявку, откройте её и измените статус. «Расписание»: записи на выбранную дату; администратор может изменить рабочие часы и выходные. «Разговоры»: история и текущие переводы. Переключатель «Доступен для перевода» разрешает новые запросы.

Клиент нажимает «Позвать сотрудника». В течение 30 секунд откройте ожидающий разговор. Для чата — «Принять разговор»; для голоса эта кнопка запрашивает микрофон и устанавливает отдельное WebRTC-соединение. Бот прекращает отвечать после фактического подключения сотрудника. Если сотрудник не ответил, бот возвращается; если недоступен, предложена форма обратного звонка.

«База знаний»: редактор сохраняет черновик. Кнопка «Опубликовать» делает конкретную версию доступной помощнику. Непубликованные изменения и архив не попадают в ответы. Услуги и цены редактируются отдельным каталогом. Права оператора не разрешают менять знания, каталог, расписание или удалять персональные данные.

## CRM и ошибки

Сначала запись сохраняется транзакцией в PostgreSQL. Outbox затем создаёт Lead, Call и Task в настоящей EspoCRM. Call/Task связаны с Lead. Повторная доставка проверяет `cVoiceActionId`; в CRM на поле установлен уникальный индекс. Разные подтверждённые обращения с одним телефоном не объединяются автоматически. API-пользователь может создавать/читать/редактировать эти три сущности; чтение User требуется EspoCRM для проверки ссылки ответственного, изменение пользователей и администрирование не разрешены.

«Заявка сохранена» означает подтверждённую запись в PostgreSQL. Пока CRM недоступна, кабинет показывает «Ожидает». На вкладке «Система» видны попытки, ошибки и кнопка повтора. Автоматические повторы выполняются с увеличивающейся паузой до 300 секунд. После неизвестного результата POST worker ищет запись по action id, прежде чем создавать новую.

Если языковая модель недоступна, чат сообщает об этом, а форма записи и обратного звонка продолжают работать. Пока голосовые модели не готовы, голосовой звонок не принимается. Допускается один активный голосовой разговор; второй получает понятный отказ, а не занимает очередь моделей.

## Сеть

Текущий профиль поддерживает localhost и LAN HTTPS. На Mac: http://127.0.0.1:7860/. На телефоне: https://192.168.1.119:8443/. Откройте http://192.168.1.119:8765/ для установки локального CA по инструкции iPhone/Android. CA общий для текущего стенда; закрытый ключ не публикуется. Native Caddy проксирует gateway; Docker Caddy не используется. ICE содержит loopback и LAN-адрес.

При изменении Wi-Fi/IP выполните `.venv/bin/python scripts/setup_lan.py --ip НОВЫЙ_IP`, обновите SIP-конфигурацию через `.venv/bin/python scripts/setup_sip.py` и перезапустите launcher. Убедитесь, что HOST/allowed origins и сертификат соответствуют адресу.

Доступ через интернет требует отдельной настройки TLS, NAT и собственного TURN. На физических iPhone/Android пользователь подтвердил первоначальный двусторонний звук в Wi-Fi; новая версия голосов/STT требует повторной проверки. Мобильный интернет и внешние сети ещё не проверены. Gateway, CRM, БД и LLM привязаны к loopback; не открывайте модель, CRM API-ключ или БД напрямую в интернет.

## Данные и резервные копии

Сессия действует час, операторская cookie — восемь часов, текст и контакты — 30 дней по умолчанию. Фоновая очистка удаляет текст и черновики, обезличивает заявку, action result и outbox, отзывает ссылку и ставит обезличивание CRM в очередь. Ручное удаление администратором дополнительно отменяет запись. Исторический факт операции и audit без текста разговора сохраняются. Политика резервных копий отдельная: старый backup содержит данные на момент создания, его нужно удалять самостоятельно по выбранному сроку.

```sh
.venv/bin/python scripts/backup.py
.venv/bin/python scripts/backup.py --restore backups/ИМЯ/voice.dump
```

Backup включает PostgreSQL приложения, PostgreSQL CRM, custom metadata и приватную конфигурацию. Каталог имеет права `700`, конфигурация и дампы — `600`; шифрование этим скриптом не выполняется. Restore восстанавливает только приложение в отдельную `voice_restore_test`, сверяет число записей и не заменяет рабочую БД. Для полного аварийного восстановления CRM разверните чистый compose-профиль, восстановите `crm.dump` через `pg_restore`, верните custom metadata/config из архива, запустите `bin/command rebuild`, затем перенесите `voice.dump` и приватную конфигурацию. Это полный ручной путь, не автоматический production restore.

## Проверки

```sh
.venv/bin/python -m pytest -q
.venv/bin/ruff check app scripts tests
npm ci
npx playwright install chromium
.venv/bin/python scripts/voice_fixture.py
npm run check
npm test
```

Серверные тесты создают отдельные временные PostgreSQL databases и удаляют только их. Browser tests требуют запущенного приложения, настоящих моделей и CRM; используют вымышленные контакты. Проверки оставляют тестовые обращения в кабинете. Голосовые browser tests используют WAV как виртуальный микрофон и проверяют реальный вход/выход RTC; они не заменяют прослушивание людьми и испытания физических устройств.

Журналы находятся в `artifacts/`, ошибки очереди — в БД и кабинете. HTTP access log выключен, URL не содержит клиентских или операторских токенов; body с токеном управления не журналируется. Метрики показывают время отдельных серверных операций, а не p95 задержки до слышимого пользователем звука.

## Голоса и каналы

На Mac ARM используются whisper.cpp/Metal large-v3-turbo q5 и MLX Qwen3-TTS Base 0.6B 8bit. Два синтетических эталона лежат в `app/assets/voices`; реальные человеческие записи для создания персонажей не использовались. Геннадий ускорен на 10% через потоковый Rubber Band R3 с сохранением тона. Мария полностью заменена другим эталоном. Не удаляйте рабочие веса и эти эталоны.

Режимы переключаются в кабинете: сайт, Telegram, SIP. SIP-образ собирается `docker build -t voice-desk-asterisk:22.11.0 infra/sip`; после успешной сборки запускайте `scripts/setup_sip.py`. Этот скрипт сохраняет прежние пароли аккаунтов, создаёт только compose-проект `voice-desk-sip`, хранит конфигурацию в `~/.cache/voice-desk/private/sip`. При повторной генерации работающая АТС должна перечитать настройки: `docker exec voice-desk-sip-pbx-1 asterisk -rx 'module reload res_pjsip.so'` и `docker exec voice-desk-sip-pbx-1 asterisk -rx 'dialplan reload'`. Не выводите dialplan/config в общий журнал: они содержат служебный ключ.

Для SIP-клиента в Wi-Fi используйте [Linphone](https://www.linphone.org/en/download/): добавьте собственный SIP-аккаунт, сервер/порт и пароль из кабинета. SIP-транк и внешний номер не требуются для локальных звонков.

Для обычных звонков Telegram подключите отдельный аккаунт помощника через кабинет. [Получение API ID/hash](https://core.telegram.org/api/obtaining_api_id). Не вводите данные в чат. Сессия и конфигурация находятся в `~/.cache/voice-desk/private/telegram`, с правами каталога 700 и файлов 600. Внешняя проверка Telegram остаётся незавершённой до входа и реального звонка.

Python bytecode и Node dependencies размещены вне iCloud. Проект в Documents должен оставаться загруженным. Храните не менее нескольких ГБ свободного места; при заполнении диска Docker может остановиться. Не очищайте volumes базы или чужие контейнеры. Неиспользуемые исследовательские модели удалены; они восстанавливаются по revisions из manifest.

Новые приватные каталоги Telegram/SIP пока не входят в старый backup-скрипт. Добавьте их в защищённый backup и проверьте восстановление перед эксплуатацией с реальными клиентами.
