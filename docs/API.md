# API v1

Источник контрактов — `docs/openapi.json`, экспортированный с работающего приложения. На сервере: `/openapi.json` и локальный справочник `/docs`. Справочник не зависит от внешних CDN.

| Ресурс | Операции | Доступ |
|---|---|---|
| `/health/live`, `/health/ready` | Готовность приложения и компонентов | Публичный |
| `/services`, `/slots?service_id=&day=` | Каталог, свободные слоты на дату | Публичный |
| `/sessions` | POST с channel/consent → UUID и секрет сессии | Публичный, rate limit |
| `/sessions/{id}` | История, текущий draft, подтверждённые actions; DELETE завершает | Bearer токен именно этой сессии |
| `/sessions/{id}/messages` | POST text и UUID idempotency_key | Токен сессии |
| `/sessions/{id}/drafts/bookings` | Подготовка деталей записи | Токен сессии |
| `/sessions/{id}/drafts/callbacks` | Подготовка обратного звонка | Токен сессии |
| `/sessions/{id}/drafts/{draft}/confirmations` | POST revision/idempotency_key | Токен сессии, актуальная версия |
| `/sessions/{id}/offer` | WebRTC SDP offer → answer | Голосовая сессия, один активный звонок |
| `/sessions/{id}/handoffs` | Запрос сотрудника | Токен сессии |
| `/sessions/{id}/events` | WebSocket, первый JSON содержит token или operator=true | Origin + токен либо operator cookie |
| `/bookings/management` | POST секретный token → одна запись | Отдельный токен записи |
| `/bookings/management/changes` | Preview; отдельный POST с confirm=true и revision | Токен записи, актуальная версия |
| `/operator/login`, `/operator/logout`, `/operator/me` | Роль и операторская cookie | Пароль; далее cookie |
| `/operator/overview`, `/requests`, `/bookings`, `/sessions`, `/outbox`, `/metrics` | Кабинет, состояния, метрики | Оператор/администратор |
| `/operator/knowledge`, `/services`, `/schedule` | Чтение конфигурации | Оператор/администратор |
| Изменение/публикация знаний, каталог, расписание, удаление данных, audit | Управление | Только администратор |

Все пути таблицы имеют префикс `/api/v1`. Запросы JSON проверяются Pydantic. Максимум HTTP body 128 KB, WebSocket message 4 KB при штатном launcher; текст 2000 символов. Запись требует телефон в E.164 с явным кодом страны; входные даты должны содержать часовой пояс.

Ошибки: `{"error":{"code":"slot_taken","message":"…","request_id":"…"}}`. Валидация добавляет список `fields`, не эхо секретного входного payload. HTTP 401 — нет/истёк доступ; 403 — роль/Origin; 404 — ресурс не доступен; 409 — занят слот, устаревшая версия или конфликт ключа; 422 — невалидные поля; 429 — лимит; 503 — компонент недоступен. API ответы имеют `Cache-Control: no-store`.

Список обращений: `limit` 1–100, `before` из `next_cursor`, status и search. Audit: cursor по ID, 50 записей. Остальные небольшие списки ограничены 100, история — 100 последних реплик для клиента и 200 для оператора; календарь — выбранная дата. Каталог рассчитан на одну небольшую организацию. Для большого каталога и истории потребуется расширить пагинацию.

Идемпотентность подтверждения защищена UNIQUE(idempotency_key), UNIQUE(draft_id), блокировкой сессии и транзакцией. Одинаковый ключ с другим текстом/сессией/draft отклоняется. Повтор успешного подтверждения возвращает тот же action. Пересечение времени защищено PostgreSQL EXCLUDE, а не только SELECT свободного слота. Опубликованная версия знаний отделена от редактируемой; запись запоминает название и цену на момент подтверждения.

Изменения v1 пока только добавочные. Удаление обязательных полей, смена смыслов и форматов требуют v2.
